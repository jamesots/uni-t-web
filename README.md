# UT61E+ over WebHID

A browser client for the UNI-T UT61E+ multimeter, talking to the WCH CH9329
(D-09A) USB cable that enumerates as `1a86:e429` — "WCH UART TO KB-MS".

Live readout in the meter's own units, rolling chart, running statistics,
hold/relative, and CSV export. One self-contained `index.html`, no build step
and no dependencies.

(Note, almost all generated by Claude and only tested on my multimeter.)

## Try it out

Visit https://jamesots.github.io/uni-t-web/

## Features

- **Meter-native readout.** Shows `120.13 mV`, matching the LCD digit for
  digit, rather than a normalised `0.12013 V`. The SI prefix comes from the
  mode/range factor and the digit count from the decimal-point position, so
  autoranging is followed automatically — including Ω → kΩ → MΩ.
- **Mode and range** are shown as a badge above the reading.
- **Rolling chart** over 30s / 2m / 10m / all, with hover crosshair and
  tooltip. **Pause chart** freezes the view at an instant while recording
  continues underneath, so the trace can be read without it sliding away.
- **Y axis** is autoscaled by default, or can be fixed to an explicit min and
  max. Switching to Fixed prefills from whatever is on screen so the view does
  not jump; an inverted range is rejected; and if the meter autoranges under a
  fixed window the bounds are rescaled (0–2 V becomes 0–2000 mV) so the window
  stays physically the same.
- **Sustained zero readings are marked.** Three or more consecutive exact
  zeros are shaded and labelled `zero` on the chart — usually an open lead or a
  probe that has come off rather than a real measurement, and otherwise
  indistinguishable from a genuine flat trace at zero.
- **History survives autoranging, not function changes.** Samples are held in
  base SI units, so mV AC → V AC or µA DC → mA DC keeps the chart, since those
  differ only by scale. A change of function — V AC → V DC, volts → ohms,
  diode → continuity — clears it. The grouping is in `FUNCTION_GROUP`.
- **Statistics** — minimum, maximum, average and span since the last reset.
  Formatted at the meter's own resolution while the window sits in one range,
  and with per-value SI prefixes once it spans an autorange, so an earlier
  2.2 kΩ does not collapse to "0.00 MΩ".
- **Hold** freezes the displayed value while sampling continues.
  **Relative** zeroes against a reference reading and applies to the chart and
  stats too.
- **CSV export** of every buffered sample: ISO timestamp, elapsed seconds,
  value in base SI units, unit, mode and range. The buffer is capped at 50,000
  samples.
- **Auto-connect.** Once the meter has been authorised in this browser, the
  page reconnects on load and on hotplug, with no clicking. The *Connect
  meter* button only appears when a grant is still needed, because
  `requestDevice()` requires a user gesture.
- **Meter annunciators.** HOLD, REL, MIN and MAX set with the meter's own
  buttons are shown as a badge beside the mode.
- **Diagnostics** are collapsed out of the way: the colour-coded raw report,
  and an event log.

Despite that product string the cable is **not** a keyboard emulator. Its HID
report descriptor is vendor-defined (usage page `0xFFA0`) with 64-byte
input/output reports and no report IDs, which is exactly what WebHID handles.

## Running

WebHID needs a secure context, so serve it rather than opening the file
directly:

```bash
cd /home/james/devroot/uni-t-web
python3 -m http.server 8000
```

Then open <http://localhost:8000> in **Chrome, Edge or Opera** on desktop. The
first time, click *Connect meter* and pick the device from the browser's
dialog; after that the page connects by itself on load.

Firefox and Safari do not implement WebHID, and neither does Chrome on
Android. There is no flag that changes this.

## Linux permissions

Chrome reaches HID devices via `/dev/hidraw*`, so the device node has to be
readable by your user. The rule at `/etc/udev/rules.d/70-ut61ep.rules` already
does this:

```
SUBSYSTEM=="hidraw", ATTRS{idVendor}=="1a86", ATTRS{idProduct}=="e429", MODE="0660", GROUP="plugdev"
```

If the meter does not appear in the chooser, confirm the node is group
`plugdev` rather than `root`:

```bash
lsusb -d 1a86:e429
ls -l /dev/hidraw*
```

## Why WebHID and not WebUSB

WebUSB refuses to claim HID-class interfaces — HID is on Chrome's protected
interface class list alongside audio, video, mass storage and smart card.
`claimInterface()` on this device throws *"An attempt to claim a USB device
interface has been blocked because it implements a protected interface
class."* WebHID exists for this case and does not blocklist this vendor.

## CH9329 framing

The page never sends anything to the meter. The CP2110 tools poll with a
request (`ab cd 03 5e 01 d9`) for every reading, but on this cable readings
stream unprompted as soon as the meter is on — confirmed with the meter and
cable power-cycled and no request ever sent.

Each reading arrives as `13 ab cd 10 ...`. The cable prefixes it with a byte
count: `0x13` is 19, the length of the meter's 19-byte message (`ab cd 10`
plus 16 payload bytes).

This matters because it shifts every offset by one relative to the CP2110 path
that [mwuertinger/ut61ep](https://github.com/mwuertinger/ut61ep) assumes, and
relative to [pof2/unit161d](https://github.com/pof2/unit161d), which indexes
from zero. Rather than hardcode the shift, this page scans the first few bytes
for the `ab cd` header and indexes relative to it, so it works with or without
the length prefix.

## Frame layout

Confirmed against a UT61E+ on a CH9329 cable (a negative V DC reading):

```
idx  00 01 02 03 04 05 06 07 08 09 0a 0b 0c 0d 0e 0f 10 11 12
     13 ab cd 10 02 30 2d 30 2e 30 30 30 32 00 00 30 30 31 03
      |  |  |  |  |  |  |  `---- value ---'        |     |
      |  |  |  |  |  |  |      "0.0002"            |     |
      |  |  |  |  |  |  |                          |     `- sign byte, bit 0
      |  |  |  |  |  |  `- sign separator          `- meter flags
      |  |  |  |  |  `- range, low nibble
      |  |  |  |  `- mode (0x02 = V DC)
      |  |  |  `- message length (0x10 = 16 bytes follow)
      |  `--'- constant preamble
      `- CH9329 byte count (0x13 = 19)
```

| Offset from `ab` | Field |
|---|---|
| 0–2 | `ab cd <len>` |
| +3 | mode |
| +4 | range, low nibble |
| +5 | sign separator: `0x20` positive, `0x2d` negative |
| +6…+11 | value, 6 ASCII characters |
| +14 | meter flags, low nibble: bit 0 REL, bit 1 HOLD, bit 2 MIN, bit 3 MAX |
| +16 | sign byte, bit 0 set when negative, bit 3 selects AC/DC in auto mode |

Two things to note:

- **These are one byte earlier than
  [mwuertinger/ut61ep](https://github.com/mwuertinger/ut61ep) uses**, which
  targets the CP2110. Do not port its offsets across unchanged.
- **The separator is a sign character, not always a space.** A parser that
  anchors on `0x20` silently fails on every negative reading.

Because the number of bytes before the header depends on the transport (the
CH9329 length byte is visible to WebHID but hidden by hidapi), the parser
anchors on the sign separator in each frame and derives the other offsets from
it, rather than indexing from a fixed position. A frame with no separator is
not a reading and is skipped, with a count and a hex capture shown in
Diagnostics. It is never decoded on a guess — doing so turned the range byte
`0x30` into a phantom `V AC`.

Values are stored in base SI units for the chart, statistics and CSV, and
rendered in the meter's own units for the readout.
